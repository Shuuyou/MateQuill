# 从自然工作信号到可执行 brief：研究与实现决策

研究截点：2026-10-24。范围是本店经授权的店员对话、录音转写与已有消息；目标是减少重复建档和需求填写，不推测微信好友购买阶段。此文在本轮实现前完成。

## 已核对的学界工作

1. [LongMemEval（ICLR 2025，2024-10 首发）](https://arxiv.org/abs/2410.10813)：将提取、跨会话推理、时间、知识更新与拒答分别评价。迁移到本项目：留住来源回合与时间；新信息不静默覆盖旧观察；没有原话不能填客户阶段。
2. [Mem0（2025-04-28）](https://arxiv.org/abs/2504.19413)：以选择性提取和检索替代无限拼接历史。借鉴紧凑上下文与来源组织，不把该论文数据集上的指标移植为我们的门店效果。
3. [LongMemEval-V2（2026-05）](https://xiaowu0162.github.io/longmemeval-v2/)：评价工作流、环境状态变化、经验与前提识别。项目应验收“旧活动失效”“原话撤回”“换店隔离”，而非只验收记得一个偏好。
4. [LazyMem v2（2026-07-28）](https://arxiv.org/abs/2607.22690v2)：将构建记忆延后到查询期，保留细节、按当前任务选择。迁移决策：低成本保存经脱敏的工作片段；由现有 Agent 在需要时提取有证据的 brief，不为每条输入额外调用一个总结模型。
5. [LycheeMemory V2（2026-10-14 修订）](https://arxiv.org/abs/2608.12990v2)：用语义片段及类型化记录减少逐回合整合开销。迁移决策：工作线索、产品事实、明确偏好分类型，不把偶发咨询固化为长期客群画像。不声称实现或训练了论文模型。

## 业界实践

[Anthropic Context Engineering（2025-09-29）](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)强调选择与维护当前推理真正需要的上下文。项目已有有界工具循环，优先扩展真实工具和来源合同；不因引入“记忆”重写整个框架。

## 实现决定与竞争差异

- 在真实用户回合入队的同一事务捕获工作线索，Web 与已认证 IM 连接器共用；店员不额外填写客户表。
- 工作线索是有来源的观察，不是自动新增的用户指令、偏好或产品事实。手机号、邮箱等直接标识脱敏。
- 读取按租户、门店、所有者/群可见性、来源仍可访问、有效期、撤回状态控制。读取私聊不会因店长或另一个门店拥有更大后台角色而被注入其 Agent。
- Agent 工具仅允许从实际读取片段中选择逐字字段，并建立 brief；不允许填入原话中不存在的预算、身份或购买阶段。Agent 仍可在独立的创作策略中提出明确标注的编辑假设。
- brief 在本轮生成时自动进入需求上下文；价格、兼容性与产品参数仍从产品证据/授权规则获取。资料不是指令，不能覆盖系统与权限。
- 明确偏好继续使用原 `remember` 路径；历史改稿事件不自动成为新任务偏好。

相对知客需要先绑定咨询再组织 brief，本轮方向是自动捕获现有自然交互、按任务选择来源并直接准备创作；优势需由集成验收证明，不能以读过论文代替实际结果。

## 验收

来源逐字绑定、伪造预算拒绝、消息时间/撤回、跨门店和跨所有者隔离、群不读私聊、PII 脱敏、幂等捕获、IM/Web 共用入队、brief 确实进入生成、显式偏好不被工作线索污染。先用隔离数据库和可注入工具做确定性验证，再由真实模型执行一个自然咨询→brief→成稿用例。
