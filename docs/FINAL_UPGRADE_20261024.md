# MateQuill 决赛升级：从竞品差距到可验证交付

研究截止日：2026-10-24。本轮采用三个并行实现组，先查原论文、作者项目与官方工程资料，再在现有产品中接入。目标不是复制竞品按钮，而是让销售员更少输入、让总部更容易协同，让实际输出可以使用。

## 已落地的六条能力链

| 竞品启发与业务差距 | MateQuill 本轮实现 | 实际入口 |
| --- | --- | --- |
| 打开后仍需店员想选题、填写表单 | 无总部分配任务时，按当前门店准备每日提案；读取目录、近期作品并研究地点，保存到同一可继续对话 | 首页每日建议；`/api/store/daily` |
| 标题有钩子，正文却没有给读者回报 | 按教程、决策、体验、情绪、观察等意图建立读者价值契约；审校定位具体公开文字，修订使用现有预算 | 成稿生成与局部改稿工作流 |
| 各店只替换地名，重复讲同一种故事 | 只读取有权共享的方案与已审核作品，比较顾客任务、本地观察、叙事及画面结构，自动选主候选；共同产品事实保持不动 | 总部活动方案与单店创意探索 |
| 日常咨询无法自然转成创作需求 | 实际文字/语音原话形成有期限的工作线索；Agent 在当前任务选择相关原话并构建带引用的需求简报 | 对话的 `read_work_signals` → `prepare_work_brief` → 创作 |
| 展示好看，复制出去却难用 | 公众号预览、富文本和离线包共用排版；朋友圈提供文字复制和原图包；包绑定已保存版本及实际图字节 | 成稿工作区的发布准备操作 |
| 模型解释价格，却缺少可执行的价格合同 | 独立审批规则和资格；整数分与 Decimal 计算，最多12条优惠精确枚举，双向叠加、互斥、封顶及有效期重验 | `read_price_rules` → `prepare_quote` → 实时报价卡 |

## 研究与实现决策

- [主动门店 Agent](FINAL_DAILY_AGENT_RESEARCH_20261024.md)：主动研究、真实工具执行和持久检查点，区分建议与已完成作品。
- [读者价值验收](FINAL_READER_VALUE_RESEARCH_20261024.md)：Self-Refine、LLM-as-a-Judge 与2026年评估研究，落实具体任务标准和实际交付面。
- [区域多样性](FINAL_REGIONAL_DIVERSITY_RESEARCH_20261024.md)：MMR、覆盖选择、语义表示及2026年多模态表示工作；先保障权限和事实不受误伤。
- [工作线索与记忆](FINAL_WORK_SIGNALS_RESEARCH_20261024.md)：LongMemEval、2026年记忆评测与选择性上下文工程；不要求销售员先建 CRM 档案。
- [平台原生交付](FINAL_PUBLICATION_RESEARCH_20261024.md)及[实现说明](FINAL_PUBLICATION_IMPLEMENTATION_20261024.md)：同一渲染源、版本绑定、富文本与实际原图交付。
- [确定性价格](FINAL_PRICING_RESEARCH_20261024.md)：Shopify 2026-10 折扣合同、微软优惠并发规则与 Decimal。

研究提供设计依据，不等于已经取得论文基准最优结果或营销转化提升。业务效果需要后续门店试用、采用率与实际咨询反馈验证。

本轮关键测试覆盖真实租户身份、跨店/跨企业隔离、撤回与过期、幂等、同源图文版本、标题回报、局部修改边界、优惠最优组合和旧报价失效。

```powershell
cd web-next

npm run build
```

真实服务验收使用隔离数据库、真实模型和冻结源码，原始结果保留在忽略的 `runtime` 目录。失败记录不覆盖为成功。`scripts/verify_final_daily_agent_20261024.py` 用新身份和真实门店地址验证一次自主准备；不预置客群或生成结果。`scripts/verify_final_embeddings_20261024.py` 只发送公开合成选题，验证真实向量和候选选择。

2026-10-24 已实际调用 `text-embedding-3-large`，返回3个3072维向量。测试中课堂整理两种表达余弦相似度0.75526，课堂整理与夜景选题0.29777；候选选择采用不同夜景方向，输入未被修改。这是接口与选择链路的实测，不是领域阈值校准或完整中文营销基准。

### 真实链路结果

最终统一回归：`python -m pytest -q --disable-warnings --maxfail=1`，1649 passed、6 skipped、3 warnings，286.09秒。首次全量检查发现一个旧测试夹具未返回新增读者价值结构，补齐夹具后专项47项通过，再重跑全量取得上述结果；未关闭生产审校要求。最终 Next.js 16.4.2 production build 与 TypeScript 均通过。6项跳过不计入通过数。

- 福雷德第二轮自主准备110.3秒完成，无客群答案、零总部分配任务；实际两次地理检索后比较人群，选择学生任务。成稿和体验方案已保存，采用进入原对话；刷新不重复调用，另一门店读取保持空闲，跨店采用404。详见[完整验收](FINAL_DAILY_AGENT_ACCEPTANCE_20261024.md)。
- 当前源码隔离预览通过真实浏览器点击：首页建议打开实际成稿，无请求拦截或模拟结果，无页面脚本错误。
- 浏览器真实复制的内容与当前编辑框一致（归一化系统换行）；纯文案不显示空的“下载配图包”。本地预览地址`http://127.0.0.1:3004/`，API为8026；数据来自成功隔离验收库的独立备份，原3003/8000与远程服务未替换。
- 32.4秒完成实际局部改稿；仅标题改变，原稿、其他文字和图片保持，纯文案交付范围保留，新读者价值契约绑定新稿。真实用户输入被工作线索捕获，系统的每日任务指令没有被当成用户原话。
- 主体辨识仍是质量校准点：一次改稿标题“一天换三个地方，电脑是真沉”存在把生活痛点误归到推广产品的阅读风险。增加通用主体辨识标准后，独立真实复核仍判通过，不能声称该语义反例已经解决。该记录保留为后续盲评样本，不以合成测试代替真实判断。
- 平台交付验证包括真实租户及实际图字节、跨企业拒绝、旧内容版本409；公众号实际编辑器保存未完成联调。报价验证使用明确演示规则和真实临时租户流程，不产生实际门店价格或交易。

## 演示建议

1. 打开福雷德广场店，展示自动研究与已保存的本店建议，店员不用填人群表。
2. 进入同一对话，用一句真实咨询或一张现场照片继续；展示问题如何成为创作需求。
3. 打开文案和体验步骤，说“只改标题，图片保持”，比较局部变化与保留内容。
4. 复制朋友圈文字、下载原图包；切换公众号展示与离线包一致的排版。
5. 总部打开同一活动的两店方向，展示顾客任务与本地观察差异。
6. 使用明确标识的演示价格规则展示核价；变更规则后，旧卡片即时失效。

每日建议为进入工作台触发的准备，不冒称已部署定时巡店任务。图文包是准备交付，真实平台账号发布与发布结果仍需各平台授权及实测。价格示例必须保留演示标识，真实门店报价须来自当前审批规则。
