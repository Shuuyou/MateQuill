# 主动本店今日提案：研究与实施依据

研究截止：2026-10-24。本文只依赖论文原页、作者项目及官方技术文章；把研究结论迁移为可测试的产品机制，不宣称本项目已达到这些论文基准的 SOTA 分数。

## 核查过的原始资料

1. **Proactive Agent: Shifting LLM Agents from Reactive Responses to Active Assistance**，2024-10-16 首次提交，ICLR 2025。原论文：https://arxiv.org/abs/2410.12361；作者项目：https://github.com/thunlp/ProactiveAgent 。该工作把是否主动提供帮助作为可由接受/拒绝评价的决策问题，而非一直输出建议。迁移到门店：前台展示一个有来源、可采用的方向；既有任务、已拒绝/已采用记录和当日预算决定是否再发起准备。不能把多生成几条等同于主动能力，也不凭模拟销量得出“本店最该卖哪款”。

2. **ProEvent: An Event-centric Benchmark for Proactive Agents**，2026-07-20 首次提交。原论文：https://arxiv.org/abs/2607.17701 。它将事件状态更新、取消与多步正确性纳入主动辅助评测，揭示只会触发建议而不能撤销过期意图的问题。迁移：每日提案绑定中国时区工作日、门店资料版本与有效期；活动取消、地点资料更新、日界限变化会让旧提案失效，不能把昨天的开售、过期补贴写成今天的理由。

3. **Generative Agents: Interactive Simulacra of Human Behavior**，2023-04-07 首次提交。论文：https://arxiv.org/abs/2304.03442；作者项目：https://github.com/joonspk-research/generative_agents 。观察、记忆检索和规划共同支撑连续行为。迁移的是“以真实历史与来源支撑下一步”而不是模拟顾客人格：沿用 MateQuill 已授权门店、工作记忆、真实公开地点研究和准确产品目录，模型自己选择研究与创作工具，提案与后续稿件保存在同一对话。

4. **Building effective agents**，Anthropic 官方，2024-12-19。https://www.anthropic.com/research/building-effective-agents 。该文区分模型动态选择工具的 Agent 与固定代码工作流，并建议优先简单可组合结构。迁移：不新建一个只有“推荐”名字的模板引擎，直接把每日准备接到现有 GTM Agent 的研究、地点消歧、产品精读、机会计划及真实生成工具；日界限、授权、缓存、幂等由确定性代码保障。

5. **Making it easier to build human-in-the-loop agents with interrupt**，LangChain 官方，2024-12-14。https://www.langchain.com/blog/making-it-easier-to-build-human-in-the-loop-agents-with-interrupt 。持久化 checkpoint 允许暂停、检查和恢复，后续操作不必把整条工作流重放。迁移：每日提案提交后立即返回持久化对话/turn 引用；首页只读轮询恢复，网络中断不重发模型创作；采用发生在服务端资源上，不接受浏览器伪造计划或作品 ID。这里复用自有队列，不为引用文章额外引入 LangGraph。

## 对当前产品的决定

- **无需总部活动也能主动准备。** 已有 assignment 继续走原授权活动链路；无 assignment 时，首页请求自己的每日提案，服务端读取当前门店资料并向现有 GTM 队列提交一次自主研究/文稿任务。没有适合的准确产品或地点歧义时，由 Agent 提出必要问题，不默认校园模板。
- **一个可用方向，按需深入。** 默认先给自然朋友圈文稿与三分钟体验思路，采用后进入该真实对话，保留工作记忆、改稿、配图和来源能力；不让店员再填人群表或选择多个 CRM 字段。
- **采用前可以预备，但不自动发布。** 一次准备真实运行研究与文稿生成；已有任务只复用，重新访问首页不会再花一次。图片等高成本动作由实际需求触发，提案不能把尚未完成的配图算作已交付。
- **时效是产品行为。** key 包含租户、本人、当前门店及中国时区日期，记录本店资料版本；每次读取重新授权并检查日期/版本/到期时间。陈旧结果不作为“今日已准备好”展示；正在执行但资料发生变化时不自动创建并发新任务。
- **价格与活动不靠推荐模型回忆。** 自主任务明确要求优惠、库存和活动只使用当前获准证据；没有时效证据就不做价格承诺。不会从社区地理资料、旧稿或销量 fixture 推出优惠与真实人群比例。
- **不要伪造定时调度。** 本轮实现的是首页到访触发、持久化后台预备和恢复；未运行的 cron、外部平台自动发布、真实经营 ROI 不写成已经部署。

## 验证标准

1. 无 assignment 的新门店首页能真实提交现有 Agent 队列，使用本店名称/地址但不塞预设受众。
2. 重复进入、并发点击与 HTTP 重试复用同一个当日任务，不重复执行已完成工具。
3. 跨用户、跨门店、跨企业读取被拒绝；作用域切换后不把旧卡显示在新门店。
4. 日界限、资料版本变更和显式拒绝/采用有可观察的状态变化。
5. 注入测试调用真实 enqueue/repository 边界；不通过替换模型结果假装真实地理搜索。真实模型验收由主协调统一启动，并分别记录实际工具、来源、稿件与消费。
