# MateQuill 图文表达迭代与真实对照

研究截止2026-10-24。文字、视觉、质量评测三个子Agent先研究后实现；本轮主协调对实际模型输出、持久状态和原生渲染执行验证。

## 改动

- 规划与写作读取同一`editorial_voice`，使用当前原话、真实可见素材、发布身份和具体叙述动作；场景提案不冒充已经发生的接待或亲测。
- 去除普遍的“困扰→参数→到店邀请”写作结构及会把修复拉回该结构的编辑警告。观察、态度、轻幽默、留白和不购买的结尾都可成立；明确商业活动要求仍保留。
- 原生视觉合同进入实际规划、原图合成及抽象设计层入口。已授权现场图、可见photo层与明确保留意图同时成立时，不生成无必要底板；记录源SHA和显示变换。该证明不等于事件或产品身份真实。
- 同一次独立审校增加普通读者的阅读顺序与正确发布身份；不增加“AI味分”、默认高分、偏好分数或额外生产judge。
- 图上短文案使用逐卡严格引用合同；纯产品名与能力承诺分开处理，不给模型补引用、不把拒绝改为通过。
- 内容模型与GTM规划解耦。`CONTENT_BASE_URL`、`CONTENT_API_KEY`、`CONTENT_MODEL`原子配置；全空保留旧连接，半配置明确失败，不能借另一服务的key或静默跨服务重抽。

研究依据分别见[文字](LIVING_COPY_RESEARCH_20261024.md)、[视觉](LIVING_VISUAL_RESEARCH_20261024.md)、[质量](LIVING_QUALITY_RESEARCH_20261024.md)、[规划接线](LIVING_PLANNING_RESEARCH_20261024.md)。使用Gacha/DivLM等研究启发不等于已部署其训练方法或取得论文指标。

## 真实实验协议

旧源码冻结于`5d64e0d`，新版与后续内容模型分工各自冻结，记录逐文件SHA。每次运行使用新隔离账号/数据库，只给定任务与场景，不将其写成Agent自主发现。产品资料与图片快照相同，不复制私人门店数据库或provider配置。

先用相同模型配置做两个任务的新旧对照，再增加显式`gpt-6.1-sol`内容角色作为独立实验条件。后者同时包含通用操作/物理量审校指引变化，不能声称是单一因素模型因果实验。所有请求与失败保留，不编辑原始正文，不把同一个未知付费请求重放。

原始报告在忽略目录`runtime/living-quality-20261024-183211`。人工评阅页不带新旧/模型标签，版本映射留在页目录之外；真实人工反馈目前为0。

## 文案结果

| 条件 | 校园任务 | 收工任务 |
| --- | --- | --- |
| 旧实现、原模型 | ready；42.24秒、5次调用 | ready；57.45秒、8次调用 |
| 首轮新表达、原模型 | ready；81.32秒、11次调用 | ready；43.33秒、5次调用 |
| 显式6.1 Sol内容角色 | ready；274.34秒、8次调用 | ready；177.47秒、5次调用 |

`ready`是系统当时的判定，不代表这些原稿都合适发表。人工检查发现：首轮新表达的校园稿编出“把纸页对折夹进电脑再合盖”的方法；收工稿把屏幕对角线写成机身尺寸。追加通用指引后，原模型的独立复核仍都判通过，不能声称提示词已修好两种错误。

更强模型的独立复核对收工稿定位了量纲对象错误；校园稿该次请求HTTP524而未完成判断，不计作识别或通过。其额外图片caption反馈也不全当成正确结论。模型请求名与服务返回名不构成实际权重或官方服务认证。

显式内容角色随后实际生成了两份新稿：校园稿“收包在一起，落座各一边”，不再建议把纸塞进电脑；收工稿“卖电脑的，也劝你合上”，以电脑让位于晚饭的生活画面结束，没有硬加CTA。这是少量真实示例，不构成总体质量胜率或流量/成交提升。它同时说明质量和时延存在真实取舍。

官方参数依据：[6.1 Sol模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[Astra模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)。内容角色在明确配置这些推理模型时使用low effort和`max_completion_tokens`，总完成上限沿用调用者预算，不能保证所有上游524因此消失。

## 交付与验证

可用`scripts/build_living_content_review.py`将两份实际正文及PNG/JPEG/WEBP打包成离线随机A/B页，填写反馈后下载；来源映射单独保存，不嵌入页面。无需注册或上传投票。

本轮最后一次完整回归取得1728 passed、6 skipped（3 warnings）；随后新增的每日内容角色版本失效测试另做定向验证，不与全量计数相加。像素测试使用明确合成源图做RGB核验，不能称作门店实拍评测。真实图制作的阻断与完成状态单独记录，不把中间规划或合成测试算最终配图。

本地试用沿用`http://localhost:3004/`，仅在确认无进行中任务后更新自有API；远程阿里云和魔搭不在本轮自动替换。


## 实际配图交付

最终单图通过真实排队任务完成，耗时393.86秒，输出PNG SHA256为`5e9437d359a9894b5e25271acaa6b73ad773630703b4969812e24ce96c70b9fb`。无标题、参数、按钮或其他叠加文案；原生渲染源文件SHA与实际产品图一致，未生成替代设备或场景。素材是官方产品生活方式资料图，不是门店实拍。

视觉审阅指出：上下等量宽色带挤压照片面积，图片自身的专属创意偏弱，不能把它宣传成已经达到优质门店随手拍的效果。正文与配图在“合盖、回到生活”层面一致，但图片未独立表现晚饭与桌面场景。这份真实结果作为后续优化取景、素材选择的依据。进一步追踪发现本次plan虽要求全幅照片，素材角色编译仍采用contain；因此“提示词里禁止装裱”本身不能证明实际交付已经去除色带。
