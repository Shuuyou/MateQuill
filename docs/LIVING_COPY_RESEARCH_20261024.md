# 门店文字的现场感与表达多样性：研究及实现

调研截至2026-10-24。先阅读当前生产生成路径，再查原论文与经营者资料。本文不把文学创作实验直接当成中文消费电子营销效果，不声称完成了小红书原生爆款数据集。

## 研究依据与适用范围

1. **We're Different, We're the Same（2025-01-31，arXiv v1）**：跨模型创意输出仍高度相似。启发是不能仅靠换模型或多抽一次降低模板趋同；需要使素材和叙述决策真正进入生成条件。[原论文](https://arxiv.org/abs/2501.19361)。
2. **DPWriter（2026-01-14，arXiv v1）**：在规划阶段显式分支，结合训练奖励改善写作多样性。它是训练方法，本项目不声称已训练DPWriter；借鉴先改变叙述规划，再展开措辞的结构。[原论文](https://arxiv.org/abs/2601.09609)。
3. **Gacha Decoding（2026-10-01，arXiv v1）**：全文把多样性放到语义决策空间，区分选项枚举、外部选择及后续实现，而非单靠token温度。我们不部署论文的完整多轮RNG harness，也不搬用论文数值；在现有一次探索调用中明确当前素材、叙述动作、展开与结束方式的不同决策，保持原调用预算。[原文](https://arxiv.org/abs/2610.01382)、[全文](https://arxiv.org/html/2610.01382v1)。
4. **DivLM / Improving Diversity in LLM Short Story Generation（2026-10-05初版，10-06 v2）**：分别处理体裁、口吻、风格与实体，并通过后训练优化多样性。短篇故事结果不等于门店文案结果；本轮不微调模型，仅借鉴拆开叙述维度，避免把多样性当作同一句话换词。[原论文v2](https://arxiv.org/abs/2610.06729v2)。
5. **大唐回浦经营者门店页**：实际展示零售门店、试用、维修、回收、配件及产品分类等具体经营接点。它支持“门店有具体服务与实物过程可表达”，不证明任意华为门店都具备相同能力，也不是朋友圈/小红书爆款样本。[经营者页面](https://www.0576sj.com/stores/24)。

### 可公开核验的身份与表达对照

- [喀什古城万达广场官方微博原帖的新浪页](https://www.sina.cn/news/detail/5217384881460973.html)，页面明确2025-10-02及商场官方身份：围绕真实开业地点和具体参与方式组织行动，表达很强促销；不能因为口语词多就认定更像店员日常，也不能将当年的抽奖礼品带入当前任务。它属于商场经营方的门店活动内容，不是店员个人号。
- [“请不要叫我测评君”的门店购机经历原帖](https://weibo.com/2/detail/5349631052743332)：页面可见10-2，未显示完整年份，因此不将其用作新产品时间或在售事实。它的可借鉴点是目的、问店、等待、正在发生的另一件事形成具体因果；这是作者自己的经历，门店账号不能把他的第一人称与等待细节移植为自己的接待故事。

两者均没有获得可信完整转化数据，不能以其写法认定爆款；也没有把微博样本当成已取得的小红书原生笔记。产品型号与体验陈述不从这些帖子导入本项目的事实库。

本轮搜索到原生平台索引不完整；高校实习一线复盘页面再次访问超时，未拿未打开的内容充当新证据。既有门店研究中的历史案例只作问题发现，不复制文案或把旧事件当当前活动。

## 当前实现的根因

`account_voice`已经允许口语和幽默，但系统提示仍普遍要求“一个选择难题”“像一次自然询问”“结尾围绕具体任务交流”；`editorial_review`在不少小红书意图下对没有互动问题发警告。结果容易成为“困扰—一项参数—来店试试”的稳定模式。仅加口语词、emoji、升温或再抽几稿不会解除这一结构。

## 本轮落地选择

- 新增无网络、无模型调用、无用户画像表单的`editorial_voice`契约，供创意规划与最终写作共同使用。真实图片的可见场景与当前需求分别标记来源；公开地理情境和构思不能变成店员已发生经历。
- 当前用户原话作为表达材料保留，不强制改成标准广告句；保留节奏、具体物件和允许的轻幽默，而不是表面加“家人们”。身份明确为门店、店员、区域或品牌，不伪装消费者。
- 由当前选题选择观察、判断、动作、轻微反差等具体叙述推进；这是一组语义决策指引，不是固定四段、三句、热词库或随机贴模板。正文、图卡和结尾可以各自承担不同工作。
- 结束可落在画面、态度、实际答案、一个与内容相关的问题或必要商业行动；不要求所有内容问读者、邀到店或做教程。用户明确的活动目标及必带文案仍保留。
- 撤除“没有互动问题本身就是问题”的普遍编辑警告，保留篇幅、事实、来源、图片关联和既有独立审校。没有“活人分”、固定禁词替换器或伪造热榜。
- 追踪确认编辑warning会触发真实repair，因此将“只保留困扰与回应”等反馈改为删重复铺垫、保留本篇观察/态度；所有长度与段落阈值保持。`preview_content_plan`仅用于无模型结构演练，仍保留演练标识，但不再默认客户阻碍、核对条件或电脑固定封面。
- 契约随服务端真实创意执行记录持久化；修订沿用当前任务、实际素材及已选概念，不能从历史样稿搬用户经历。

## 验证方式

测试验证素材数据投影与隐私边界、身份与平台区分、修订不扩大事实、成稿payload与执行记录真正接入、没有新增模型调用，以及没有CTA的有效观察/选购内容不被机械提醒互动。它们验证工程契约，不把合成测试通过算作真人偏好或真实传播效果。

本Agent完成后：54项声音/新契约/读者价值/自然策略测试通过，另109项生成、执行持久化、事实选择、朋友圈、局部修订和Planner相关回归通过。主协调仍需统一验收其他并行模块以及实际新旧生成。

最终文本质量由主协调使用相同门店、相同产品资料和相同原始输入做新旧真实生成对照；保留失败输出，比较具体观察、说话身份、读者回报、事实准确与可发布性，不把更长、更多emoji或自评分更高当胜出。

## 可选内容模型角色

2026-10-24另按OpenAI Docs重新检索并实际打开[GPT-6 Astra官方模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)与[GPT-6.1 Sol官方模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。官方将Astra定位为最具能力的复杂任务模型，6.1 Sol定位为接近Astra能力的成本折衷，并建议在自身任务上比较。此定位不证明任何模型已在中文门店营销中最优，第三方兼容endpoint的同名模型也不据此变成官方服务。

新增`app/content_models.py`的`build_content_model(calls,tokens,timeout,configuration)`，复用既有`OpenAICompatibleLLM`及调用预算：`CONTENT_BASE_URL`、`CONTENT_API_KEY`、`CONTENT_MODEL`三项全空时保持原LLM连接；完整填写才选专用内容服务；部分填写明确报配置错误，不将旧服务KEY发往新地址，也不读取IMAGE/DESIGN凭证。factory不发请求、不加第二套judge、不在服务失败后换模型重抽。API/Agent实际调用点由主协调接线，真实A/B完成后才在本地私密环境显式启用。

12项factory专项测试通过：原服务与调用预算保留、完整独立角色、6种半配置拒绝、空白配置、公共配置与repr不暴露新凭证、原硬上限保留，以及真实客户端经MockTransport返回503时仅发送一次到选定内容服务、不会把原服务或图片密钥作为回退。

后续按[官方GPT-6指南](https://developers.openai.com/api/docs/guides/latest-model)和[reasoning说明](https://developers.openai.com/api/docs/guides/reasoning?api-mode=chat)补充显式内容角色的wire适配：仅完整配置的`gpt-6-astra`/`gpt-6.1-sol`使用`reasoning_effort=low`与`max_completion_tokens`，移除旧`temperature`/`max_tokens`。Chat Completions这里只传文本JSON，没有工具调用；官方将这两型号的工具调用安排在Responses接口。适配保持调用者原有效token上限与调用次数，不沿用设计客户端9000token的下限，也不配置额外快速服务档位。其他内容模型和原LLM全空回退的wire完全不变。

适配后factory专项共19项通过，包含两个型号的完整请求体、原LLM回退保持、其他型号保持、实际客户端MockTransport发出的适配请求与调用预算。总完成上限也需覆盖推理消耗，较低effort和相同上限不保证完整长JSON；实际服务兼容、超时与成稿质量仍由主协调的真实同输入验收决定，不能把参数调整当作524已解决。
