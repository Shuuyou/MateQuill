# 区域与同店连续内容多样性：研究与实现依据（2026-10-24）

## 研究结论

不能把“换标题”“去掉相同字串”当作千店千面。应把产品事实与创意分开：相同型号的参数、适用条件、活动必带文案允许重复；比较对象是顾客任务、具体本地观察、叙事动作和视觉结构。Agent 先生成多个有依据的候选，再结合本店相关性与历史覆盖自动选一份主方案，备选按需展开。

这是将成熟信息检索/摘要选择方法用于门店创作的工程设计，不将它称为新的SOTA算法，也不宣称能预测平台推流。以下原始论文发布日期均早于本次截止日；官方文档在2026-10-24核查。

## 原始研究与官方依据

1. **Goldstein / Carbonell，1998，MMR。** 在相关性与相对于已选内容的冗余之间做边际取舍。适合候选重新排序；本项目把“本店/当前任务适配”作为相关性，把已采用的观察与任务相似度作为冗余，不能直接套全文相似度。
   原文：[ACL Anthology X98-1025](https://aclanthology.org/X98-1025/)。
2. **Lin / Bilmes，ACL 2011，覆盖与多样性的子模函数。** 可用递减收益覆盖选择一组内容，避免所有候选反复讲一个信息点。此处采用明确的维度覆盖边际收益，不声称任意混合分数都满足论文的近似保证。
   原文：[A Class of Submodular Functions for Document Summarization](https://aclanthology.org/P11-1052/)。
3. **SemDeDup，2023-03-16。** 证明预训练表示可以找出字面不一致的相近样本。论文对象是训练数据去重，不是营销效果；启发我们区分词面重复与概念重复，但不直接照搬论文阈值或数据删除比例。
   原文：[arXiv:2303.09540](https://arxiv.org/abs/2303.09540)。
4. **Qwen3 Embedding，2025-06-05，作者论文与官方模型。** 提供多语言文本表示/排序模型，可作为实验室自部署表示服务的候选。模型选择和中文营销相似阈值仍需领域样本校准，不因官方榜单就宣称在本任务最优。
   原文：[arXiv:2506.05176](https://arxiv.org/abs/2506.05176)；[作者官方仓库](https://github.com/QwenLM/Qwen3-Embedding)；[官方0.6B模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)。
5. **Sentence Transformers 官方 STS 文档。** 先实际计算表示向量，再用余弦等相似函数。没有表示模型调用时，不能把字面重合或手写规则标作嵌入语义结果。
   [官方文档](https://sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)。

## 本次落地决策

### 2026新增工作与现行业界核查

- **Qwen3-VL-Embedding / Reranker（2026-01-07官方发布，论文2026-01-08）**把文字、图像、截图、视频纳入统一表示；这比仅用2025文字模型更贴近“观察与视觉重复”。不过作者也指出同等尺寸纯文本多语能力仍与文字专用模型存在差异。当前落地先比较经过规划器描述的视觉结构，不将文字描述相似度冒充成品像素相似度。未来需把实际导出图送入已配置的多模态服务并校准后，才增加像素级语义去重。
  [官方发布](https://qwen.ai/blog?id=qwen3-vl-embedding)；[论文](https://arxiv.org/abs/2601.04720)。
- **Qdrant 原生MMR（v1.15.0，官方实践2025-09-04）**截至本次核查仍使用相关性/多样性权衡，并强调候选池应大于最终返回数。这支持我们内部生成4–6候选、只自动采用1份，而非为了算法新颖堆更多强制用户选择。
  [官方实践](https://qdrant.tech/blog/mmr-diversity-aware-reranking/)；[官方搜索文档](https://qdrant.tech/documentation/search/search-relevance/)。
- **选择理由：**需要同时解决权限、地方观察、事实共用、候选数量与表示服务失败；更大的多模态模型不会自动解决这些业务约束。MMR/覆盖提供可解释的选择层，现代多语表示提供可选的异表同义信号，结构化任务/观察提供稳定的权限内回退。两层组合比把全文向量阈值当平台重复判定更适合当前门店任务。

- 历史仅来自当前租户、当前真实权限能读到的明确共享方案，以及审核通过/已确认发布的共享稿件。SQL先排除private，随后通过中央授权门；不读取私聊、未共享草稿，也不把管理员的全读权限当作可以泄露给别店的许可。
- 候选分解为顾客任务、本地观察、叙事角度和视觉结构；事实ID不参与重复惩罚，必要的产品值/条件原句从文本比较输入中剥离。相同产品可有不同观察，不能因共用事实被判为重复。
- 自动选择采用“本任务质量/适配先验 + 新覆盖收益 - 任务/观察重复惩罚”的MMR式排序，并以稳定ID打破平分。嵌入为可配置的真实批量服务调用；未配置/失败明确记录为结构化特征模式，不伪造向量结果。
- 默认Agent自动采用最合适主候选。区域运营可以按需查看选择依据及备选；店员不需要每次挑三稿，也不新增画像填写。
- 区域准备必须使用候选选择结果入库、采用与后续生成；单店探索必须读取当前已授权共享历史并把避免重复的观察约束传给生成/局部改稿，不做闲置评分工具。
- 方案资料/权限变化需要重新校验；网络/表示服务失败保留可用候选和明确降级状态，不能显示“语义审查成功”。无有效候选时不返回虚构成功。

## 验证计划

共同参数/条件不误伤；异表同义顾客任务识别；不同本地观察增加覆盖；同店连续作品轮换；跨租户/无权门店/私有资源不入上下文；排序稳定；表示服务真实调用与失败状态；区域准备的主候选真实入库及生成要求承接。真实模型与最终界面验收由主协调统一执行。

## 已接线的实现与本地验证

- `app/regional_diversity.py`：共享历史投影、事实剥离、可选真实表示服务、自动主选与覆盖报告。
- `app/creative_exploration.py`：写作前探索直接读取当前门店已授权共享历史，选择结果进入现有writer的editorial_concept。
- `app/channel_opportunities.py`：区域内部3–4候选、选择与共享入库；采用后把同一主方案传入真实生成任务；HQ可按需选择已核验备选。
- `CampaignOpportunities.tsx`：默认直接展示Agent已选主方案，其他观察角度折叠，切换调用实际服务端资源更新。
- 表示服务配置：`DIVERSITY_EMBEDDING_BASE_URL`、`DIVERSITY_EMBEDDING_MODEL`、可选`DIVERSITY_EMBEDDING_API_KEY`；批量调用`/embeddings`，只允许HTTPS远端或HTTP loopback。没有配置时报告`facet_mmr/not_configured`，失败报告`failed`，不宣称实际算过语义向量。视觉维度当前是规划器的结构描述，不是成品像素表示。
- `python -m pytest tests/test_regional_diversity.py tests/test_channel_opportunities.py tests/test_creative_exploration.py -q`：37 passed。前端`npm run typecheck`通过。没有重启、部署或自行发起真实付费模型验收。
