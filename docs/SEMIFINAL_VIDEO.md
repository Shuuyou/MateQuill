# MateQuill 复赛视频录制脚本

建议成片时长 3 分 45 秒，16:9、1080p。主角是一位正在接待顾客的门店销售员：他把工作中已有的素材和问题交给 MateQuill，带走可以编辑、可以分享的内容。视频里的操作和结果均取自本次实际运行；生成等待可以剪辑压缩，用字幕标注“等待过程已加速”。

## 已提供的讲解剪辑生成工具

`scripts/build_semifinal_video.py` 可将实际验收截图、中文合成配音与逐句字幕合成为 1920×1080 MP4。它使用 Windows 已安装的慧慧语音，并通过 Pillow、`imageio-ffmpeg` 生成品牌讲解画面。视频内标注“产品实机画面 · 讲解剪辑”，不会把截图剪辑表述为连续录屏。

```powershell
python scripts/build_semifinal_video.py --screenshots output/semifinal/screenshots --output output/semifinal
```

输出包含 MP4、SRT、逐镜头时间线和独立配音文件，可替换为团队本人配音继续剪辑。所需截图来自本次实际浏览器操作；门店示例与合成示范录音在旁白中明确说明。

## 录制前准备

- 准备一张有权使用的产品或门店实拍照片、一段本人录制的自然语音，以及一份真实新品官方资料。拍摄顾客入镜时先取得同意，也可只拍产品和空景。
- 在产品里手动创建三个画像，名称明确填写“演示门店·校园”“演示门店·商务”“演示门店·创作”。这些是体验产品能力的示范配置，画面和字幕保持“演示门店”名称。
- 三店分别填写主要顾客与核心任务：新生与家长／入学选电脑；常出差的职场人／会议资料整理；设计专业学生／课程交稿。不要额外填写虚构地址、销量、顾客评价或活动优惠。
- 选一款资料齐全的真实产品作为同款三店演示对象；再选资料明确支持组合展示的电脑、手机或平板，按具体型号准备生态场景。
- 先完整走一遍计划录制的路线，检查照片预览、语音转写、必要追问、成稿、编辑与导出。首次创建门店和新品资料也可提前录成短片。
- 关闭聊天窗口、密钥设置页和无关通知。视频展示产品能力，凭证不入镜。

## 推荐的真实输入

**拍照加一句话：**“这张是我们准备使用的产品实拍。帮我给新生和家长写一篇小红书，回答买电脑前应该先确认什么。产品用本次选择的准确型号。”

**必要追问：**输入带系列名称、尚未明确版本的产品需求，让系统按实际识别结果询问。录制时保留真实问题和回答，不添加不存在的追问。

**三店同款：**“同一款新品，为这三家演示门店分别准备适合各自顾客的推广内容，目标是引出具体咨询。”

**新品导入：**“根据刚导入的新品资料，为第一次了解这款产品的人整理购买前关心的问题。”

**生态场景：**“围绕从手机收集资料、到电脑整理内容的任务，准备一篇生态使用内容。以本次选择设备的真实支持能力组织表达。”最终使用哪个场景，由已选型号与资料决定。

## 成片检查

1. 所有操作来自真实运行，旁白与画面显示的功能一致。产品发布结果展示到可复制或可导出的实际交付状态。
2. 三店在画面中始终保留“演示门店”名称；使用真实创建的画像生成，内容差异落在顾客任务、结构与画面上。
3. 产品名称、型号、来源与正文保持对应；生态片段保留必要的具体型号与条件。
4. 文字足够清楚，鼠标停留给观众阅读。用全屏成品和局部放大展示成果，避免整段视频只停在输入框。
5. 数字只使用实际测量或实际运行结果。规划中的结构差异与最终文稿的多样性分开表述。
6. 片尾放实际演示地址、公开仓库和团队姓名；提交前按主办方最新通知核对渠道，截止时间为 10 月 23 日 17:00。

## 工程验证

后端运行后，可执行只读检查：

```powershell
python scripts/check_semifinal_demo.py --base-url http://127.0.0.1:8000 --frontend-url http://127.0.0.1:3001
```

该脚本读取健康状态、产品目录、真实门店数量和 API 契约，不创建资料或门店。添加 `--run-id` 可检查一份已经在应用里生成的结果是否可导出。拍照、语音与成稿效果仍以录制前的实际操作走查为准。
