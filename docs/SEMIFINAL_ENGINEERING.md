# MateQuill 复赛工程说明

更新：2026 年 10 月 20 日。本文面向继续开发、测试和部署的维护者，描述当前代码的实际行为。

## 系统组成

`web-next` 是 Next.js 16 前端；Python FastAPI 提供生成、素材、产品知识、门店和推广计划接口。生成仍然使用同一条 `AgentWorkflow`，拍照、语音、新品和门店计划通过结构化任务接入已有生成与审校流程，避免为各入口维护不同版本的产品判断逻辑。

| 模块 | 职责 | 扩展方式 |
| --- | --- | --- |
| `app/intake.py` | 自然需求解析与必要澄清 | 扩展型号别名和任务字段解析，保留未明确输入的澄清状态 |
| `app/media_intake.py`、`media_routes.py` | 图片规范化、视觉观测、语音转写、私有预览 | 通过现有兼容服务配置替换视觉或 ASR 模型 |
| `app/store_campaigns.py`、`campaign_routes.py` | 门店画像持久化、差异化推广规划 | 扩展选题、叙事和视觉轴，计划继续产出标准 `TaskInput` |
| `app/product_knowledge.py`、`product_routes.py` | 新品资料预览、确认入库、生态能力规划 | 将新来源转为可确认的事实、原文和限定条件 |
| `app/task_context.py` | 合并明确选择的生态设备和门店素材 | 保留每个事实的产品归属，上传观测独立存放 |
| `app/local_knowledge.py` | 产品目录、资料及官方素材适配 | 接入新的已核对产品记录与有哈希的素材 |
| `app/workflow.py`、`editorial.py` | 生成编排、事实与参数检查、图片用途审查 | 新增可解释规则和对应行为测试 |
| `app/creative_connectors/` | 平台编辑策略、分镜结构及审查 | 注册实现协议的连接器，复用统一证据对象 |
| `app/run_records.py` | 服务重启后恢复最近生成结果 | 保持已清洗记录结构，使用独立 SQLite 存储 |

## 从真实素材到任务

照片和录音使用 `POST /api/media/intake`，提交 `multipart/form-data`：`file` 加 `kind=photo|audio`。响应由 Pydantic 模型定义，包含素材 ID、状态、转写、视觉观测、预览地址和后续问题。

状态为 `ready`、`needs_configuration` 或 `retryable`。识别未完成时仍保留实际上传素材，界面可继续文字输入或重新上传；不会填充示例转写、示例图片分析。

图片在解码前检查上传大小，限制为 12 MiB；只接收可实际解码的 JPEG、PNG 和 WebP。解码时检查像素数量，按 EXIF 方向旋转，最长边缩放至 2400 像素，重新编码为 JPEG。保存的图片不携带原 EXIF/GPS 信息。

视觉模型只产出场景描述、短文字、候选名称和场景线索。候选产品名称必须能在本次返回的可见文字中定位；它们用于进一步确认选择，不进入产品事实表。密集屏幕或文章截图只摘录短标签，输出截断时至多再请求一次更短的观测。

音频根据文件头识别 WAV、MP3、M4A、WebM、Ogg 或 FLAC，不依赖用户提供的文件名。文件大小限制为 12 MiB，WAV 校验两分钟时长；前端录音应在两分钟内结束。ASR 使用真实 `/v1/audio/transcriptions`，转写返回空文本时进入可恢复状态。

当前兼容服务已实际验证 `gpt-4o-mini-transcribe` 中文转写，以及 `gpt-4o` 图片观测。测试音频使用 Qwen 官方公开中文样例，照片使用仓库已收集的华为官方素材。这是接口能力验证；产品表现仍应使用门店真实输入继续评估。

## 千店千面的生成路径

门店画像包括名称、主要顾客、关键任务、表达风格、位置及素材描述。推广规划从选题、叙事和视觉三个独立轴选择方向，并输出每家店的选题原因、行动引导和标准生成任务。

方向选择考虑门店任务信号和本次计划内的差异，生成结果继续经过原有事实与内容审查。`diversity` 字段衡量的是规划字段差异，不能将它解释为真实投放效果或文稿语义相似度评测。

门店画像和素材描述是选题上下文。门店位置不自动推断附近学校、人流或顾客偏好；素材描述不自动变成已上传的照片；设想的拍摄方案不自动变成已发生的接待记录。

## 新品与华为生态的知识边界

新品资料先生成预览草稿，用户确认后才进入产品库。记录保留原文、事实、来源地址、内容哈希、资料采集时间和确认时间。新产品不需要等待底座语言模型重新训练，确认后的资料直接参与同一事实检索流程。

生态任务显式选择主设备与伴随设备。`TaskContextProvider` 合并各设备资料，事实保留自身的 `product` 和来源；审查只允许本次选定产品范围内的事实和素材。跨设备功能使用具体能力记录及适用条件，不能因为同时选择手机和平板就推断它们支持某一协同功能。

正文检查会区分型号中的数字与参数数字。例如，选中 `HUAWEI Mate 80` 后，正文中的 `Mate 80` 不会被当作无依据参数；`80GB` 或另一款 `Mate 800` 仍然接受证据检查。

上传照片作为 `store_upload` 场景素材接入，OCR 和照片描述不进入 `facts`。用户上传图片可以表达真实门店场景，但不能通过 `supported_fact_ids` 充当产品参数或功能证明，也不能改标为官方产品素材。

## 持久化与恢复

| 数据 | 默认位置 | 行为 |
| --- | --- | --- |
| 门店与推广计划 | `runtime/stores.sqlite3` | 门店及计划跨请求、跨进程恢复；初次使用通过 `PRAGMA user_version` 迁移表结构 |
| 新品草稿和确认资料 | `runtime/knowledge/products.sqlite3` | 草稿确认后写入产品记录；已确认草稿不可重复确认 |
| 上传照片与录音 | `runtime/media-intake/` | 随机 ID 文件及 SQLite 索引；24 小时、最多 100 条、总计 256 MiB 保留预算 |
| 生成记录 | `runtime/records/runs.sqlite3` | 保存最近 200 条已清洗生成记录；同秒写入以 rowid 再排序，保留最新写入 |

`MATEQUILL_STORE_DB` 可以指定门店数据库位置。其默认路径相对于工作目录；运维启动时应固定工作目录或提供明确路径。其余上述默认路径按项目根目录计算。

上传素材预览使用随机 ID 查询索引，不接受任意本地文件路径。响应设置 `private, no-store` 和 `nosniff`。过期素材返回 404，用户重新上传即可继续。持久生成记录可能比上传素材保留更久，因此需要长期保存的交付物应在素材有效期内导出。

备份应使用 SQLite 自带备份能力获取一致快照，同时保存仍需使用的上传文件与官方素材。源码仓库的 `runtime/` 被忽略；运行数据应按部署实例管理，不复制到公开代码仓库。

模型凭证通过进程环境或部署 Secret 配置，不写入这些业务数据库。`ASR_BASE_URL`、`ASR_API_KEY`、`ASR_MODEL` 控制语音服务；照片使用现有 `IMAGE_BASE_URL`、`IMAGE_API_KEY` 和 `IMAGE_REVIEW_MODEL`。服务商模型列表只用于发现；实际转写或视觉请求成功才构成接口能力验证。

## 修改与验证约定

新增生成入口优先输出 `TaskInput`，让事实、引用、限定条件、图片用途和平台审查继续集中在同一流程。新增产品先验证目录和资料归属，再验证跨设备能力。修改素材用途时应同时检查正文配图及创意卡片，避免只修改某个渲染入口。

后端回归执行 `python -m pytest -q`。当前已覆盖素材伪装、上传大小、EXIF 清理、模型异常恢复、空转写、OCR 与产品事实隔离、生态产品范围、新品确认、数据库恢复、并发首次建库、推广计划原子性及型号数字检查。

测试通过说明这些行为在测试条件下成立。外部模型接口的真实验证另行记录，避免将 Mock 单元测试计为真实模型效果评测。
